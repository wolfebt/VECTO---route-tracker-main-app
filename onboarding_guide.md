# Welcome to VECTO Route Tracker! 🚀

Welcome to the **VECTO Route Tracker** project! This guide will help you get up to speed with the project's architecture, technology stack, and local development setup.

## 🛠 Technology Stack

VECTO is a modern, cross-platform application built using the following technologies:

- **Frontend**: [React 19](https://react.dev/) powered by [Vite](https://vitejs.dev/) for lightning-fast development.
- **State Management**: [Zustand](https://github.com/pmndrs/zustand) for lightweight, predictable global state.
- **Backend & Database**: [Firebase](https://firebase.google.com/) (Authentication, Firestore, Storage) providing a serverless backend.
- **Mobile Packaging**: [Capacitor](https://capacitorjs.com/) for compiling the web app into native iOS and Android applications.
- **Maps & Geolocation**: 
  - Google Maps via `@vis.gl/react-google-maps`.
  - Background Geolocation via `@capacitor-community/background-geolocation` and `@capacitor/geolocation`.
- **Styling**: [Tailwind CSS v4](https://tailwindcss.com/) for utility-first styling.
- **Icons**: [Lucide React](https://lucide.dev/) for clean, customizable SVG icons.

## 🏗 Project Architecture

The project is structured logically to separate UI components, global state, backend hooks, and utilities. Here is an overview of the most important directories:

```text
d:\_ Data\VECTO - route-tracker
├── android/            # Native Android wrapper generated by Capacitor
├── ios/                # Native iOS wrapper generated by Capacitor
├── src/                # Main application source code
│   ├── components/     # React UI Components
│   │   ├── jobs/       # Job-related components (e.g., JobDetails)
│   │   ├── layout/     # Structural components (MapArea, Sidebar, ToastContainer)
│   │   └── modals/     # Pop-up modals (Settings, CreateJob, Invite, Profile, etc.)
│   ├── hooks/          # Custom React hooks (useFirebase, useLocationSharing, useDirections)
│   ├── store/          # Zustand state stores (useAppStore, useToastStore)
│   ├── utils/          # Helper functions (geohash, offlineQueue for syncing)
│   ├── App.jsx         # Main application layout and routing logic
│   └── main.jsx        # React DOM entry point
├── capacitor.config.json # Configuration for native iOS/Android builds
├── firestore.rules     # Security rules for Firebase database
└── vite.config.js      # Vite build configuration
```

> [!NOTE] 
> **Mobile vs Desktop Layout**
> The application uses a dynamic layout in `App.jsx` that adapts to the device. On mobile, it utilizes a swipeable carousel or segmented controls to switch between the Map view and the Sidebar/Job view. On desktop, it shows them side-by-side.

## 🚦 Local Development Setup

Follow these steps to run the VECTO Route Tracker locally:

### 1. Install Dependencies
Make sure you have Node.js installed, then run:
```bash
npm install
```

### 2. Configure Environment Variables
Copy the `.env.example` file to create a local `.env` file:
```bash
cp .env.example .env
```
Fill in the required keys in the `.env` file:
- **Firebase Keys**: Required for connecting to the database and authentication.
- **Google Maps API Key**: Required to render the map component (`VITE_GOOGLE_MAPS_API_KEY`).
- **Gemini API Key**: Used for AI-powered features (`VITE_GEMINI_API_KEY`).

### 3. Run the Development Server
Start the Vite development server:
```bash
npm run dev
```
Open your browser to the local URL provided (usually `http://localhost:5173`).

## 📱 Mobile Development (Capacitor)

Because VECTO is built as a cross-platform app, you can test and build for mobile natively.

### Syncing Web Assets to Native Platforms
Whenever you make changes to the web application that you want to test on mobile, run a build and sync it via Capacitor:
```bash
npm run build
npx cap sync
```

### Running on Android / iOS
To open the respective native IDEs (Android Studio / Xcode):
```bash
npx cap open android
npx cap open ios
```
*Note: Make sure your local machine is set up with Android Studio (for Android) or Xcode (for macOS/iOS).*

## 🧠 Key Workflows to Understand

> [!TIP]
> **Dive deeper into these specific files to understand how VECTO works:**

1. **Authentication & Company Onboarding**
   The application uses Firebase Auth (`src/hooks/useFirebase.js`). The main layout in `App.jsx` handles routing users to an authentication screen (`Auth.jsx`), followed by a company selection flow (`CompanySelector.jsx`) if they haven't joined a team yet. `useUrlOnboarding.js` allows users to join companies or jobs via QR code or URL parameters.

2. **Location Tracking**
   Location tracking logic lives in `src/hooks/useLocationSharing.js`. It utilizes Capacitor plugins to capture user location, even in the background, and pushes these updates to Firestore. This powers the real-time map tracking feature.

3. **Offline Resilience**
   Given the nature of route tracking, the app handles offline data capture. Take a look at `src/utils/offlineQueue.js` and the `persistentLocalCache()` configuration in `src/firebase.js` to see how Firebase buffers operations when connectivity drops.

4. **Global State**
   Instead of prop-drilling, UI states like active job IDs, mobile view toggles, and modal visibility are globally managed in `src/store/useAppStore.js`.
